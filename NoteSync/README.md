# NoteSync для Блокнота Windows 11

Отдельная утилита, не изменяет основной проект Perfectify или файлы Блокнота.

## Сборка
.NET 8 SDK, PowerShell из корня репозитория:
```powershell
dotnet publish NoteSync/NoteSync.csproj -c Release -r win-x64 --self-contained true -p:PublishSingleFile=true -p:IncludeNativeLibrariesForSelfExtract=true -o NoteSync/dist
```
Запусти NoteSync/dist/NoteSync.exe. Права администратора не нужны.

## Использование
1. Открой два файла в отдельных окнах Блокнота (не вкладках одного окна).
2. Введи два имени в NoteSync. Расширения .txt, .md, .markdown необязательны. Имена могут совпадать.
3. Закрепи нужное окно PowerToys Always on Top (Win+Ctrl+T).
4. Нажми «Запустить» в NoteSync или плавающую кнопку «Синхронизация» рядом с заголовком активного окна Блокнота. Кнопка является отдельным окном, а не изменением панели самого Блокнота.
5. Перемещай курсор между пунктами. Во втором окне запрашиваются прокрутка и выделение. Кнопка позволяет остановить синхронизацию.

## Изменения 0.1.1
- События UI Automation вместо непрерывного чтения документов; резервная проверка после пользовательского ввода с интервалом не чаще 650 мс.
- Повторное выделение не выполняется, когда номер пункта не изменился; дерево редактора кэшируется.
- Целевой пункт по возможности центрируется вертикально через ScrollPattern или TextPattern. У начала и конца документа точное центрирование ограничено доступной прокруткой.
- В режиме Markdown новый пустой пункт после Enter сразу получает следующий номер; в Auto это применяется при обнаружении вставленной строки. Если Блокнот не публикует позицию/маркер через UIA, поведение требует ручной проверки.

## Нумерация
- Auto: буквальные номера; повторяющиеся маркеры в одном списке трактуются как последовательная Markdown-нумерация.
- Literal: буквальные номера, в том числе с пропусками.
- Markdown: последовательные номера начиная с первого маркера.
- Пустые строки не участвуют в счёте, маркер без текста (например, 3.) поддерживается.
- При отсутствии соответствующего номера, пустой или ненумерованной исходной строке вне нового Markdown-пункта синхронизация пропускает обновление (предыдущее выделение может остаться), а при следующем подходящем пункте продолжает работу.
- При буквальной нумерации удаление пункта не сдвигает остальные. В последовательном Markdown удаление целого элемента перенумеровывает последующие элементы по правилам списка.

## Ограничения
Требуется UI Automation TextPattern с доступными текстом, курсором, прокруткой и выделением. Видимость неактивного выделения и номера в визуальном Markdown зависят от версии Блокнота и его UIA-провайдера. Приложение не активирует другое окно и не отправляет клавиши; если редактор забирает фокус при прокрутке/выделении, сеанс приостанавливается до перезапуска. Режим «Только прокрутка» помогает, если выделение не поддерживается.
Требуются отдельные окна с различимыми заголовками; если найдено больше одной цели, синхронизация не производится. Сложные вложенные списки, одинаковые номера разных списков и скрытые UIA-маркеры не поддерживаются надёжно. Кнопка рисуется поверх Блокнота и может перекрывать часть его интерфейса. Не меняет файлы заметок, не отправляет их в сеть. Для проверки на конкретной версии Windows Notepad необходим ручной тест.
